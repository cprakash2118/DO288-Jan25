************************************** Setting up the Developer Environment *****************************
- You are going to build and deploy applications/Database on kubernetes platform (Red Hat OpenShift).
- But before writing code, you need a playgroud (Cluster) and tools (CLI + IDE + Container Engine).
  CLI - Command Line Interface 
  IDE - Integrated Development Environment 
  COntainer Engine - Crio/Containerd/Docker/Mirantis COntainer Engine/Podman etc.

##Problem Statement:-
- Why can't we just write code and run it on my local system/laptop?

Solution Statement:-
- Because Kubernetes application don't run like normal apps. Your code must be build into a container image, pushed to a registry and deployed to a cluster. SO you need:-

 1- A development cluster.
 2- CLI tools to talk to cluster (oc/kubectl can talk to OCP cluster).
 3- Container tools to build/push images 
 4- Optional IDE integration for speed.
 
##Problem Statement:-
- Choosing a Development cluster (Where you will deploy)?
  
  Option-A-# Red Hat Developer Sandbox (Managed cluster).
   - Think: "Red Hat gives you a ready cluster in cloud".
   - Pros: No local install, fast start 
   - Cons: Internet dependent, limited resources/time.

  Option-B-# OpenShift Local (CRC) - Cluster on laptop side a VM.
   - Think:- "Your create a mini OPenShift cluster locally"
   - Pros:-  Works offline after setup.
   - cons:-  Need good CPU/RAM/Disk 
   
   Option-C# Classroom cluster (Training LAB environment).
    - Think: "Course already provides a ready OPenShiftcluster + tools.
